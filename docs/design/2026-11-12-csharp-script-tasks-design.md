# C# 脚本任务设计

> 设计日期：2026-11-12
> 状态：已实现，取代 2026-11-10 的 Lua 定时任务方案

## 1. 目标

应用内维护一组由用户添加的 C# 脚本：

- 页面主要展示脚本列表；
- 通过独立对话框添加或编辑脚本；
- 编辑器提供基础 C# 词法高亮和同步行号；
- 支持仅手动、单次、每天、每周和每月执行；
- 支持立即运行、停止、超时和历史记录；
- 不关联或导入外部脚本文件；
- 不向脚本暴露应用私有 API。

脚本直接使用 .NET 10 的公开 API，例如：

- `System.Net.Http.HttpClient` 访问网络；
- `System.IO` 访问文件和目录；
- `System.Diagnostics.Process` 启动本地程序；
- `System.Text.Json` 处理 JSON。

## 2. 运行时选型

采用 `Microsoft.CodeAnalysis.CSharp.Scripting` 5.9.0：

- 目标框架为 .NET 10，与应用程序运行时一致；
- 脚本在隐藏 helper 中编译和执行，不要求目标机器安装 .NET SDK；
- 编译器和托管依赖随自包含单文件发布；
- 不提供额外的 `withwindows` 脚本 API；
- 用户脚本文本仍保存在任务文档中，不在应用目录长期保留外部源码。

## 3. 执行模型

父进程启动同一 exe 的隐藏 `--script-helper` 模式：

1. 写入一次性运行规格；
2. 启动 helper 并等待就绪事件；
3. helper 读取 `.csx` 运行副本；
4. 使用 Roslyn 编译并执行脚本；
5. 父进程持续把 stdout / stderr 写入带时间戳的日志；
6. 超时、手动停止或应用退出时终止 helper；
7. 脚本主动启动的本地程序不会随 helper 关闭而被强制终止。

helper 不使用 Kill-on-close Job Object。这样可以保留标准 .NET `Process.Start`
语义，使计算器等 GUI 程序在脚本结束后继续运行。脚本不是沙箱，以当前用户权限执行。

## 4. 错误处理

- Roslyn 编译错误写入标准错误，并包含文件、行、列和诊断文本；
- 脚本运行时异常保留异常链；
- helper 原生崩溃只影响当前脚本 helper；
- 标准输出和错误输出按实际到达顺序合并显示；
- 输出超过上限时截断，但仍继续排空管道；
- 任务或历史文件损坏时进入只读故障态，不静默覆盖。

## 5. 数据模型

任务只保存脚本文本、执行计划、超时和运行历史。运行副本使用 `.csx` 扩展名，
仍位于 `%APPDATA%\WithWindows\scheduled-tasks\scripts\`。

运行历史中的 `runtimeVersion` 记录为 `C# 14 / .NET 10`。历史日志和任务数据不会被静默丢弃。

## 6. 页面

主页面参考待办页和设置页：

- 顶部显示标题、脚本数量和“添加脚本”；
- 主体为脚本列表；
- 行内提供运行、停止、历史、编辑和删除；
- 运行中禁用编辑与删除；
- 手动运行结束后自动打开运行日志；
- 日志使用单列圆角折叠卡片，合并显示标准输出与错误输出；
- 日志使用应用内显式遮罩，可点击外部或按 `Esc` 关闭；脚本启动前台程序导致主窗口失焦时不会自动关闭；
- 计划设置在代码编辑区下方；
- 不显示运行时版本或额外提示。

编辑对话框：

- 脚本名称；
- 执行方式；
- 带基础 C# 语法高亮和行号的多行编辑区；
- 超时秒数；
- 验证错误固定在滚动区下方。

AI 对话在用户明确要求创建 C# 脚本时，只能调用 `propose_csharp_script`
生成待确认草案；确认后才保存，不自动运行或覆盖脚本。

## 7. 测试

- 手动计划不产生调度时间；
- 单次、每天、每周和每月计划按现有规则计算；
- 任务、运行历史和日志保存往返；
- C# 运行规格只接受绝对路径；
- C# 关键字、类型、字符串、注释和数字可高亮；
- 编译错误与运行时异常可回传；
- 超时和手动停止可终止 helper；
- 脚本内网络请求和子进程输出可写入标准日志；
- 脚本主动启动的程序不随 helper 关闭；
- 列表页、编辑对话框和历史对话框的可访问性标识可从 UI 树读取。
