# 待办与提醒设计

> 实现更新：Windows App SDK 2.5.1 在自包含、未打包应用中使用 `AppNotificationManager` 时存在已知原生崩溃，该系统通知方案已移除。最终实现使用同一套精确截止调度，到期后唤出主窗口、切换到待办页并显示应用内提示条。下文涉及系统 toast 的历史设计以本节为准。

## 1. 目标

在 With Windows 中新增「待办」工具页，支持：

- 添加待办；
- 将待办标记为完成或重新设为未完成；
- 删除待办；
- 为每个待办设置一个一次性本地提醒；
- 到点自动唤出主窗口、切换到待办页并显示提示条。

提醒可靠性边界是：应用正在常驻托盘时按计划提醒；应用重新启动后，对已经到期但尚未提醒的待办补发一次。应用完全退出时不会触发提醒，界面与 README 必须明确这一点。

## 2. 方案选择

采用主进程内的截止时间调度 + 应用内醒目标题条 + 独立 JSON 存储。

未采用：

- 为每个提醒创建 Windows 计划任务：可在应用退出后提醒，但会引入系统任务注册、权限、升级与卸载清理，超出本次范围；
- 只显示应用内提示：实现轻，但窗口收进托盘时容易漏提醒；
- Windows App SDK 系统通知：2.5.1 自包含应用会因通知运行时资源与隐藏启动组合触发原生崩溃；
- 固定间隔轮询：实现简单，但没有待办时仍会无意义唤醒。最终采用“只睡到最近提醒时间”的一次性后台计时器。

## 3. 数据模型与存储

待办数据保存到 `%APPDATA%\WithWindows\todos.json`，不与 `config.json` 混用。配置模型版本保持 v5。

单条待办字段：

```json
{
  "id": "5c886c7a0f4d4f81ae7ff29e73c43f5a",
  "title": "整理发布说明",
  "isCompleted": false,
  "createdAt": "2026-10-23T09:00:00+08:00",
  "completedAt": null,
  "reminderAt": "2026-10-23T18:30:00+08:00",
  "reminderDeliveredAt": null
}
```

- `id` 使用 `Guid.NewGuid().ToString("N")`。
- 日期时间统一保存为 ISO 8601，业务判断使用 UTC。
- `reminderDeliveredAt` 保证同一提醒只成功触发一次。
- 完成、重新设为未完成和删除均由仓储层持久化。
- 完成或删除待办时清除尚未触发的提醒；重新设为未完成不会自动恢复旧提醒。
- 修改提醒时间时清除 `reminderDeliveredAt`。
- 存储沿用原子写入、`.bak` 备份和损坏回退；主文件与备份都不可读时从空列表开始，并记录错误日志。

## 4. 调度与提醒

`TodoReminderScheduler` 在以下时机重新计算下一次唤醒：

- 应用启动并读取待办后；
- 添加、完成、删除或修改提醒后；
- 一次提醒处理完成后。

调度规则：

- 只考虑未完成、已设置提醒且尚未提醒的待办；
- 定时器直接等待到最早 `reminderAt`，不运行固定轮询；
- 没有待处理提醒时停用定时器；
- 定时器到期后取出所有已到期项，唤出主窗口、切换到待办页、显示应用内提示条，并写入 `reminderDeliveredAt`；
- 系统休眠导致晚期唤醒时，在唤醒后补发所有到期项；
- 单次等待上限设为一天，超过上限时先等待一天再重新计算，以削弱系统时钟调整造成的长等待。

应用内提醒：

- 后台计时器到期后通过 `DispatcherQueue` 切回主线程；
- 主窗口执行 `ShowAndNavigate("todo")`，把窗口带到前台并打开待办页；
- 页面显示 `InfoBar`，单条时显示「“标题”已到期。」，多条时逐项列出；
- UI 操作异常只记录日志，不阻塞提醒状态写回。

## 5. 页面设计

导航与托盘：

- 在 `ToolCatalog` 增加 `todo` 页面项，标题「待办」，图标使用 WinUI Gallery 的 `CheckList`（`E9D5`）；
- 托盘菜单增加「待办」入口；
- 不增加全局热键，因此 `AppConfig.KnownToolIds` 不变。

页面布局参考待办类应用，内容限宽并居中：

- 标题区显示「待办」与未完成数量摘要；
- 顶部为标题输入框和「添加」按钮，按 `Enter` 也可添加；
- 主区域使用原生 `ListView` 展示待办；
- 未完成项在前，已完成项在后；同组按创建时间排序；
- 每行包含完成复选框、标题、提醒摘要、提醒按钮和删除按钮；
- 已完成标题使用删除线与次要文字色；
- 提醒摘要显示具体的本地日期时间；已经触发时显示「已提醒」；
- 没有待办时显示空状态；
- 窄窗口下按钮不挤压标题，提醒文本可省略。

提醒编辑：

- 点击铃铛按钮打开 `ContentDialog`；
- 使用 `CalendarDatePicker` 和 `TimePicker` 选择本地日期与时间；
- 保存时校验时间必须晚于当前时间；
- 支持移除已有提醒；
- 对话框必须设置 `XamlRoot`，并使用可访问性标识。

删除：

- 点击删除按钮先弹出确认对话框，避免误删；
- 确认后立即保存并从列表移除。

所有新增交互控件必须设置稳定的英文 PascalCase `AutomationProperties.AutomationId` 和中文 `AutomationProperties.Name`。

## 6. 代码边界

`WithWindows.Core` 新增纯逻辑：

- `TodoItem` 与 `TodoDocument`；
- `TodoStore`：加载、保存、增删改、完成状态与提醒更新；
- `TodoReminderPolicy`：判断哪些项已到期、计算下一次唤醒时间；
- `TodoDisplayFormatter`：提醒时间的本地化显示文本。

`WithWindows.App` 新增：

- `TodoPage.xaml` 与 code-behind；
- `TodoReminderHost`：持有单次截止计时器并触发应用内提醒；
- `TodoReminderDialog` 或页面内对话框构建逻辑；
- 工具目录和托盘入口。

`AppHost` 持有 `TodoStore`，确保页面卸载后提醒仍可运行；提醒宿主由 `App` 字段持有到进程退出，禁止临时创建后失去引用。

## 7. 错误处理

- 待办文件损坏：回退 `.bak`；仍失败则空列表启动并记录日志；
- 保存失败：记录日志，界面给出可见错误提示，不崩溃；
- 自动唤出页面失败：记录完整异常信息，待办列表与持久化继续可用；
- 页面异步操作返回时检查 `IsLoaded` 与 `XamlRoot`，避免页面卸载后访问 XAML；
- 对话框回调中的异步异常必须捕获。

## 8. 测试与验收

Core 单元测试覆盖：

- 新文件加载、保存往返和备份回退；
- 添加、完成、重新打开、删除与提醒修改；
- 完成或删除后不再成为提醒候选；
- 多个到期项全部被筛选；
- 下一次唤醒时间取最早到期项；
- 没有候选时返回无唤醒；
- 已提醒项不会重复触发；
- 本地时间显示与空提醒文本。

界面验收：

- 解决方案构建零错误；
- Core 测试全绿；
- 启动应用后，`winapp ui inspect` 能找到待办导航、输入框、添加按钮与列表；
- `winapp ui screenshot` 检查浅色主题下无错乱；
- 实际创建一个几秒后的提醒，确认自动打开待办页并显示到期提示；
- 应用最终保持运行，供用户直接查看。
