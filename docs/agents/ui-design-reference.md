# 界面设计与无障碍参考

本文是新页面设计和界面复查的入口。写页面前先读本文，再按需查阅
`ui-baseline.md`（当前控件与 AutomationId）、`ui-conventions.md`（视觉约定）、
`winui3-hard-rules.md`（运行期硬规则）和 `development-workflow.md`（验证闭环）。

## 一、产品气质

- 这是 Windows 11 原生工具，不是品牌展示页。优先贴近系统：Mica、原生标题栏、
  系统强调色、系统字体、原生动效和标准控件。
- 视觉关键词是“安静、紧凑、可扫读”：页面有明确标题、低层级卡片、短说明和足够留白，
  不使用大面积渐变、装饰性插画或多层嵌套卡片。
- 工具页优先服务高频操作。编辑器、对话输入、待办输入等主操作要占据最稳定的位置，
  不为了装饰牺牲工作区。
- 亮色、深色和高对比度是同一套界面，不是三套主题。不得用自绘背景替代系统画刷。

## 二、不可破坏的壳层

- `MainWindow` 使用 `NavigationView` + `Frame`；页面入口由 `ToolCatalog` 生成，
  新增页面不要手工修改 `MainWindow` 的路由表。
- 标题栏使用内置 `TitleBar`，保留系统 caption 按钮；标题栏主题与托盘图标刷新必须
  避开激活回调栈，按 `winui3-hard-rules.md` 的低优先级队列方式处理。
- 窗口背景使用 `MicaBackdrop`。关闭窗口与 `Alt+F4` 隐藏到托盘，真正退出只走托盘菜单。
- 页面根容器遵循现有滚动归属：普通工具页由页面级 `ScrollViewer` 滚动，列表内部
  不重复套一层会争抢滚轮的滚动器。

## 三、页面骨架

- 普通工具页：`ScrollViewer Padding="24"`，内容最大宽度使用
  `PageContentMaxWidth`（当前 1000 DIP），窄窗口跟随可用宽度，大窗口水平居中。
- 页面标题使用 `TitleTextBlockStyle`；卡片、分组和功能项标题使用
  `BodyStrongTextBlockStyle`；说明、文件名、时间等次级信息使用
  `CaptionTextBlockStyle` 或 `TextFillColorSecondaryBrush`。
- 页面标题是 `HeadingLevel=Level1`；折叠组或一级区块是 `Level2`；组内小节是
  `Level3`。不要只靠字号表达层级。
- 工具栏和状态栏保持低视觉重量：透明背景优先；分组命令使用 `CommandBar` 或现成
  命令面，不用一排 `StackPanel + Button` 重新发明工具栏。
- 空状态使用统一字号和留白；说明文字要告诉用户“下一步做什么”，不只写“暂无数据”。

## 四、视觉系统

### 颜色与主题

- 所有颜色、字体、间距和动效使用 `ThemeResource` / 系统资源，禁止硬编码色值。
- 强调色只用于当前选择、焦点、主操作和系统强调状态；不要让多个按钮同时争夺注意力。
- 错误、警告、成功分别使用系统语义色；不得只用颜色区分状态，必须同时有文字或图标。
- 高对比度下保留系统画刷和原生控件状态，不使用自绘背景遮住系统高对比度样式。

### 字体与文案

- 中文使用中文标点，中英文和数字之间加空格；代码标识符保持原样。
- 页面标题简短，主动词优先；卡片标题描述“是什么”，说明文字补充“为什么 / 结果”。
- 按钮文案使用动词或动宾短语；重复行操作必须带上下文名称，避免多个同名“删除”。
- 不在正文堆砌格式。AI 回复可以 Markdown，工具页本身优先短句和状态文本。

### 间距与尺寸

- 页面外边距 24 DIP；页面区块间距 16 DIP；同一分组内间距 8–12 DIP。
- 普通卡片行最小高度 64 DIP；列表内图标按钮常用 36×36 DIP；输入框要保持明确的
  可点击区域，不靠极细边框制造“精致感”。
- 切换页内容区左侧 52 DIP、右侧 16 DIP，分别对齐折叠标题文字与展开箭头。
- 列表项、空状态和对话框的内部间距优先复用已有页面的节奏，不在单页重新定义一套。

### 表面与层级

- 原生 `Expander` 使用两层卡片表面：标题 `CardBackgroundFillColorDefaultBrush`，
  内容 `CardBackgroundFillColorSecondaryBrush`，中间保留 1 DIP 接缝。
- 不在卡片里再套完整卡片；功能行用透明背景和留白分组，不用第三层边框。
- 圆角优先 6 DIP（设置卡片）或 8 DIP（列表卡片）；同一页面保持一致。
- 不要为了“看起来高级”替换控件模板、修改 `Expander` 内部元素或手写高度动画。

### 图标

- 统一使用 `FontIcon` + Segoe Fluent Icons；应用图标、托盘 ICO 和系统要求的图片除外。
- 字形从 WinUI Gallery 图标表查询，不凭记忆猜码点。
- 纯图标按钮必须同时有 `AutomationProperties.Name` 和 `ToolTipService.ToolTip`。
- 装饰性图标和纯视觉标记不应进入无障碍树；需要时设置 `AccessibilityView=Raw`。

## 五、控件与交互模式

- 控件优先级：WinUI 3 内置控件与系统资源 → 白名单内控件（引入前先问）→ 自己写。
- 不为了视觉定制替换标准控件的键盘、焦点和读屏行为。需要定制时先组合、重样式，
  不要先改模板。
- 设置页采用卡片行，左侧图标 + 标题/说明，右侧开关、下拉框或操作；状态文字放在
  控件左侧，控件贴右边缘。
- 折叠组不嵌套第二层 `Expander`，不把交互控件塞进 `Tag` 或模板内部。
- 对话框必须设置 `XamlRoot`；复杂表单内容放在可滚动区域，错误/校验行固定在滚动区外。
- 页面内异步操作要保留当前页面状态，不让等待状态把工具页变成空白或不可用。
- 选择类控件的“最低两项”模式：恰好两项时锁定已选项，未选项仍可继续勾选；
  勾选第三项后全部恢复可操作，同时用动态提示解释原因。不能只禁用而不解释。

## 六、无障碍基线

### 每个交互控件

- 有稳定、英文 PascalCase 的 `AutomationProperties.AutomationId`；改名视为破坏接口。
- 有可读的 `AutomationProperties.Name`。纯文本按钮可由 `Content` 推导，图标按钮必须显式写。
- 重复出现的行操作名称必须包含对象名，例如 `运行脚本：每日摘要`、`删除待办：买牛奶`。
- 输入框、编辑器、列表和下拉框即使有相邻标签，也要给自身设置明确 `Name`，
  不依赖视觉位置推断。
- 图标或装饰性复选框使用 `AccessibilityView=Raw`，避免读屏读到无名控件。

### 状态与错误

- 异步进度、校验错误、操作失败、列表摘要和最低选择约束使用
  `AutomationProperties.LiveSetting="Polite"`；高频光标/字数变化不要设置成 Live。
- `InfoBar` 打开或内容变化时要能被读屏感知；错误同时提供文字，不只变色。
- 禁用状态必须有可见且可读的原因。禁用控件保留稳定的 AutomationId，方便自动化定位。

### 键盘与焦点

- 所有可操作元素必须能通过 `Tab` 到达；对话框打开后焦点落在首个合理控件，
  关闭后回到触发控件或主编辑区。
- 常用快捷键遵循系统习惯：`Ctrl+F` 查找、`Ctrl+H` 替换、`Ctrl+S` 另存、
  `Enter` 提交、`Shift+Enter` 换行、`Esc` 关闭/取消。
- 输入法组合期间不提交、不触发发送；录快捷键控件要明确 `Esc` 取消和清除行为。
- 页面切换后不强行把焦点打进不适合编辑的控件；编辑器类页面再主动恢复编辑焦点。

### 缩放与高对比度

- 使用 `MinHeight`/自适应布局，不把文字塞进固定高度；系统文字缩放后不能裁切。
- 不用颜色单独表达选中、错误、完成和禁用；保留系统高对比度主题和焦点视觉。
- 36 DIP 只作为列表紧凑图标按钮的基线，不做更小的鼠标/触控主操作。

### 无障碍验证

1. 解析 XAML，检查交互控件是否有 AutomationId/Name，排除 `bin/obj`。
2. 启动实际应用，用 UIA 树检查每个页面的标题、输入框、列表、开关和行操作名称。
3. 检查动态提示、校验、错误和摘要是否出现在无障碍树里，是否具备 LiveSetting。
4. 检查键盘 Tab 顺序、Esc/Enter、焦点恢复、最低选择锁定和禁用原因。
5. 检查亮色、深色和高对比度下的可读性；截图只作补充，不替代 UIA 树。

## 七、历史决策与前期要求

- 技术栈锁定 .NET 10 + WinUI 3（Windows App SDK），未打包，仅 x64；不引入 WPF、
  Windows Forms、UWP `Windows.UI.*`、WinUI 2、.NET MAUI 或 Reactor。
- 第三方依赖遵守白名单；新依赖先询问。当前不使用 CommunityToolkit 的
  `SettingsControls`，不为一个设置项引入新控件库。
- 页面保持 code-behind；当前不引入 MVVM。只有出现“一份状态 ↔ 一组控件”的设置页
  手工回写长期漏 bug、多个页面共享可变状态或派生显示文本失控时，才重新评估。
  记事页的 RichEdit/IME/焦点/光标等编辑器内部机制永远不要改成 MVVM。
- 直接参考 WinUI Gallery 和 PowerToys 的现成页面结构，不从头猜控件外观；
  图标码点以 WinUI Gallery 图标表为准。
- 像素级配色、间距和动效曲线由人确认。AI 可以按现有基线实现，但不要自行发明
  新的视觉语言。
- UI 改动完成后必须实际启动应用并保持运行；如果窗口受命令会话桌面隔离影响，
  使用用户桌面通道启动，不能用“进程存在”代替“用户看得到”。
- README、CHANGELOG、界面基线和本文件涉及的行为变化必须同步。README 六张页面截图
  保持浅色/深色各三张，截图不带桌宠、调试覆盖层或其他应用的遮挡。

## 八、新页面检查表

- [ ] 页面入口来自 `ToolCatalog`，没有手工改 `MainWindow` 路由。
- [ ] 标题、分组、正文的 HeadingLevel 清晰。
- [ ] 使用系统主题资源，亮色、深色、高对比度均可用。
- [ ] 页面最大宽度、外边距、卡片层级和间距复用现有基线。
- [ ] 所有交互控件有 AutomationId；纯图标控件和输入/列表有明确 Name。
- [ ] 重复行操作名称包含对象名，动态状态有适当 LiveSetting。
- [ ] 键盘可完成核心流程，Esc/Enter 行为符合系统习惯，焦点不会丢失。
- [ ] 文字缩放和窄窗口下没有裁切；颜色不是唯一信息来源。
- [ ] 文档、截图、README 和 CHANGELOG 已同步。
- [ ] 构建、Core 测试、实际启动和界面自检全部通过。
